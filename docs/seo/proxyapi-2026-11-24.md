# ProxyAPI: доступ к моделям без VPN и зарубежной карты (24.11.2026)

Зачем файл: замер видимости в ответах нейросетей (`tools/ai_visibility_probe.py`)
идёт через ProxyAPI. Здесь — что проверено руками, а не пересказ документации,
чтобы через месяц не искать заново и не повторять ошибок.

## Что это

OpenAI-совместимый шлюз: один ключ и один адрес на 523 модели (OpenAI, Anthropic,
Google, DeepSeek, открытые вендоры). Оплата в рублях, цены с НДС 5%.
База: `https://api.proxyapi.ru/openai/v1`. Ключ — `PROXYAPI_API_KEY` в `.env`
проекта (права 600, в git не попадает).

## Цены (₽ за 1М токенов, проверено на странице `/pricing`)

| Модель | Вход | Выход | Комментарий |
| --- | --- | --- | --- |
| `gpt-5-nano` | 13 | 104 | самый дешёвый, для черновых прогонов |
| `gpt-5-mini` | 65 | 516 | **наш выбор**: близко к тому, что отвечает ChatGPT |
| `gpt-4.1-mini` | 104 | 413 | запасной вариант |

Поиск оплачивается отдельно: **1 ₽ за поисковый запрос** (Anthropic 1 ₽, Gemini 1,5 ₽).
Один прогон аудита ≈ 2–3 ₽: токены + поиск.

## Как включить поиск

Только через **`/v1/responses`**, инструментом `tools: [{"type": "web_search"}]`.
На `/v1/chat/completions` серверного поиска нет — обычный ответ по памяти,
который для замера бесполезен: он не показывает, что видит человек в ChatGPT.

Два подводных камня, оба стоили прогонов:

1. **Имя модели — без префикса вендора.** Документация показывает
   `openai/gpt-5-mini`, но `/v1/responses` на префикс отвечает
   `400 Model not supported`. Короткое `gpt-5-mini` работает. В `/v1/models`
   при этом модель числится с префиксом. В скрипте префикс снимается
   автоматически (`api_model`).
2. **`gpt-5-search-api` в списке есть, но не работает** — `400 Model not supported`.
   Не рассчитывать на «поисковые» модели: поиск включается инструментом, а не моделью.

Третий, не технический: **решает модель, а не мы**. Если ответ ей известен, она
не пойдёт в сеть. Поэтому в запросе есть инструкция искать и называть источники,
а результат проверяется по наличию аннотаций `url_citation` — ноль ссылок значит
«поиска не было», и такой прогон нельзя считать замером выдачи.

## Что видно в кабинете

- **Биллинг:** баланс, история платежей, промокоды.
- **Логи:** по умолчанию **выключены** — запросы с содержимым не сохраняются.
  Включение отдельное и платное (10 000 запросов в месяц бесплатно, хранение
  3 дня). Значит, приватность по умолчанию нормальная, но и разобраться
  «почему прогон вернул пусто» по логам не получится, пока не включишь.
- **Потребление:** раздел есть, но графики читаются только в браузере; в отчёте
  расход считаем по числу поисковых запросов (1 ₽) и токенам.
- **Ключи:** можно ограничить бюджет, модели и список IP. Наш ключ «Тест GPT API»
  без ограничений — на клиентских прогонах так нельзя.

## Дорогие модели как явный выбор (24.11.2026)

Владелец решил: выделить 3–4 дорогие модели для сложных задач, **не** ставя их
в автоцепочки. Вызов только по имени через `omni-auto-router` на `127.0.0.1:8123`;
ключ лежит в `~/.omniroute/.env` (права 600), в `server.py` читается оттуда же.
Все четыре модели проверены реальным запросом к `https://api.proxyapi.ru/v1/chat/completions`.

| Имя для вызова | Upstream | ₽/1M вход / выход | Когда брать |
| --- | --- | --- | --- |
| `proxyapi/fable-5-2` | `anthropic/claude-fable-5-2` | 1600 / 8000 | архитектура и стратегия |
| `proxyapi/gpt-6.2-astra` | `openai/gpt-6.2-astra` | 1680 / 8400 | сложная логика и код |
| `proxyapi/gemini-4-neon` | `google/gemini-4-neon` | 910 / 4550 | длинный контекст 1,05M |
| `proxyapi/opus-5-5` | `anthropic/claude-opus-5-5` | 840 / 4200 | критичные задачи и безопасность |

Пример вызова:

```bash
curl -s -H "Content-Type: application/json" \
  -d '{"model":"proxyapi/gpt-6.2-astra","messages":[{"role":"user","content":"..."}],"max_tokens":4000}' \
  http://127.0.0.1:8123/v1/chat/completions
```

Три детали, чтобы не тратить деньги зря:

1. Reasoning-модели (`fable-5-2`, `gpt-6.2-astra`) съедают бюджет до ответа:
   `max_tokens` ниже ~2000 даёт пустой `content`. Ставьте 4000+.
2. Явно выбранная модель при ошибке **не** подменяется дешёвой цепочкой —
   возвращается 502. Это сделано намеренно: «сложная задача» не должна тихо
   решиться слабым моделем.
3. `gemini-4-argon` (1220 / 6100 ₽) намеренно не включён — по ADR-007 только
   по прямой просьбе владельца. Появляется по просьбе добавлением одной строки
   в `PROXYAPI_MODELS` в `tools/omni-auto-router/server.py`.

**OmniRoute :20128 (готово, 24.11.2026):** узел `openai-compatible-chat-premium`
(префикс `proxyapi`, база `https://api.proxyapi.ru/v1`), ключ на соединении `main`,
четыре пользовательские модели и четыре одномодельных комбо без failover:
`fable-5-2`, `gpt-6.2-astra`, `gemini-4-neon`, `opus-5-5`. Все четыре вызваны
реальным запросом через `model: "<имя>"` — HTTP 200, `OK`. Имена добавлены
в `~/.config/opencode/opencode.jsonc` в секцию `provider.omni-auto.models`.
Обычный `OMNI_API_KEY` годен только для чтения; запись — через admin-токен
из дашборда. Канал :8123 продолжает работать как резервный.

```bash
curl -s -H "Content-Type: application/json" \
  -d '{"model":"gpt-6.2-astra","messages":[{"role":"user","content":"..."}],"max_tokens":4000}' \
  http://127.0.0.1:20128/v1/chat/completions
```

## Не проверено

- Лимиты запросов в минуту (`/docs/limits` не читал).
- Поведение при 429 и таймаутах на длинных прогонах: скрипт пишет ошибку
  в отчёт и продолжает, но фактическую частоту отказов ещё не мерили.
- Стриминг и `background`-режим для долгих задач — не использовали.

## Итог для проекта

Замер возможен и стоит копейки; блокер снят. Но **API ≠ ChatGPT один в один**:
модель та же, а выдача зависит от региона, даты и настроек поиска. В отчётах
это пишем честно: «модель `gpt-5-mini` с серверным поиском, дата, регион»,
а не «как в ChatGPT у клиента».
