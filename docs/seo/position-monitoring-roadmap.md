1. Раз в неделю автоматически снимается срез: позиция по каждой фразе (Яндекс + Google, десктоп + мобильный, регион Москва/МО), показы, клики, CTR.

## 3. Фазы

### Фаза 0. Доступы и базовый контур — 1 час

1. Вебмастер: добавить `ai-traffic-pro.ru`, подтвердить владение через DNS TXT в Cloudflare (лучше, чем HTML-файл: покрывает www и поддомены). Указать регион — Москва и Московская область, основной регион Москва.
2. GSC: проверить, что свойство типа «Домен» (DNS), а не «префикс URL» — иначе часть данных по www/страницам теряется.
3. Метрика → Вебмастер: связать счётчик (в Метрике «Источники → Яндекс → Поисковые запросы»), это даёт позиции в разрезе поведения.
4. API-доступы:
   - Вебмастера: OAuth-приложение в Яндекс ID, scope `webmaster:hostinfo`, токен в GitHub Secrets (`YANDEX_WM_TOKEN`). Живёт год — поставить напоминание на перевыпуск.
   - GSC: сервисный аккаунт в Google Cloud + доступ «Полный» в Search Console на свойство, JSON-ключ в `GSC_SA_JSON`.
   - Метрики: токен `METRIKA_TOKEN` (только чтение).
5. Не делать: не заводить платный трекер, пока нет ни одного среза своих данных.

**Готово, когда:** в Вебмастере видны показы за 7 дней, в GSC — данные за 28 дней, токены лежат в Secrets.

### Фаза 1. Список фраз на мониторинг — 3 часа

Не 20 фраз, а 45–60: 20 фраз по коммерческим услугам слишком мало, чтобы отличать тренд от шума.

1. База берётся из `docs/semantics/page-map.json` (уже есть маппинг запрос→страница) — отобрать по 6–10 корней на услугу, которые реально продают, а не дают трафик.
2. Добавить гео-модификаторы: «продвижение сайта Москва», «SEO-агентство Раменское», «настройка рекламы Московская область».
3. Добавить отдельный кластер GEO/AI: «продвижение в нейросетях», «GEO продвижение», «видимость в ChatGPT», «AI SEO», «AEO» — это ваша отличительная услуга, по ней позиции в классической выдаче почти не существует, нужен отдельный замер (см. `ai-visibility-2026-11-22.md`).
4. Снять частотность через Wordstat (бесплатно, `wordstat.yandex.ru`) — по регионам 213 (Москва) и 1 (Россия). В текущем `keywords.json` частотность по вакансиям — для приоритизации она годится, для прогноза трафика нет.
5. Результат — новый файл `data/keywords-monitoring.json`:

```json
{
  "region": { "yandex": 213, "gsc_country": "rus" },
  "phrases": [
    { "phrase": "продвижение сайта москва", "cluster": "seo", "page": "/services/seo/",
      "priority": 1, "volume_msk": 1200, "engine": ["yandex", "google"] }
  ]
}
```

**Готово, когда:** 45+ фраз с посадочными и приоритетом, файл закоммичен.

### Фаза 2. Сбор данных — 4–6 часов

1. Скрипт `tools/positions/collect.py` (CLI по чек-листу CP-1: `--source webmaster|gsc|tracker|all`, `--from`, `--to`, `--dry-run`, `--help` с примерами; ошибки в stderr, код ≠ 0).
2. Источники:
   - **Вебмастер API** (`search-queries/popular`, `query-analytics`): средняя позиция по показам, показы, клики, CTR — по дням и по региону. Даёт только фразы, по которым уже были показы.
   - **GSC API** (`searchanalytics.query`, dimensions `query,date,device,country`): позиция, показы, клики. Позиция округлена и «бакетируется» — тренд виден, точная цифра нет.
   - **Трекер для фраз без показов**: Topvisor API (free-тариф, раз в неделю) — единственный источник позиции по фразам вне топа. Альтернатива на первое время: ручной сьём `yandex.ru/search/?text=<фраза>&lr=213` раз в неделю, 20–30 минут.
3. Хранение: `data/positions/YYYY-MM-DD.json` + агрегат `data/positions/latest.json`. Git как база — diff истории бесплатно и наглядно.
4. Расписание: `.github/workflows/positions.yml`, `cron: '0 3 * * 1'` (понедельник 03:00 МСК) + `workflow_dispatch`. Секреты — только в GitHub Secrets, в лог не печатать.
5. Если Яндекс отдаёт капчу на серверных запросах — не бороться, а брать трекер: парсинг выдачи своими руками = нарушение ToS и бан IP.

**Готово, когда:** два понедельника подряд появились файлы с данными, и по 10 фразам цифры совпадают с тем, что видно в интерфейсе Вебмастера.

### Фаза 3. Дашборд `/monitoring` — 6–8 часов

Делать **после** двух срезов данных, иначе это красивая пустая страница. Тонкий слой на существующем Astro, без BI и без новых зависимостей.

1. Доступ: Cloudflare Access (или Basic Auth в worker) + `noindex` + исключить из `sitemap`/`llms.txt`. Список фраз — коммерческая информация, в открытый доступ нельзя.
2. Данные: страница читает готовый `latest.json`, сгенерированный скриптом. Ключи API в браузер не попадают никогда.
3. Блоки (в этом порядке важности):
   - **Кластеры**: доля фраз в топ-3 / топ-10 / топ-30 и «взвешенная видимость» (Σ показов × вес позиции). Это главная цифра «стало лучше или хуже», а не средняя позиция.
   - **Фразы**: таблица — позиция сейчас, неделю назад, Δ, показы, клики, CTR, посадочная. Сортировка по Δ и по приоритету.
   - **Вне топа**: фразы с позицией >50 или без показов — отдельный список «здесь мы невидимы».
   - **Посадочные**: показы/клики/CTR по страницам + заявки из Метрики (`lead_submit`, `phone_click`) — связка «позиция → деньги».
   - **История**: спарклайн за 90 дней по каждой фразе (инлайновый SVG, без chart-библиотек).
   - **Лента**: авто-записи «фраза X упала с 4 на 11», «страница Y потеряла 40 % показов».
4. Контракт данных (фиксируется до вёрстки):

```json
{
  "generatedAt": "2026-11-30T03:00:00+03:00",
  "region": 213,
  "clusters": [{ "id": "seo", "top3": 2, "top10": 5, "top30": 8, "visibility": 0.34 }],
  "phrases": [{ "phrase": "...", "cluster": "seo", "page": "/services/seo/",
    "yandex": { "position": 7, "prev": 12, "impressions": 340, "clicks": 18, "ctr": 0.053 },
    "google": { "position": 11, "prev": 9, "impressions": 120, "clicks": 4, "ctr": 0.033 },
    "source": "webmaster|gsc|tracker", "history": [12, 11, 9, 7] }],
  "landing": [{ "page": "/services/seo/", "impressions": 900, "clicks": 40, "leads": 3 }],
  "alerts": [{ "level": "warn", "text": "..." }]
}
```

**Готово, когда:** открывается по ссылке на телефоне, грузится <1 с, и по ней можно за 30 секунд ответить «что упало и что выросло».

### Фаза 4. Алерты и ритм — 2 часа

1. В том же workflow после сбора: если фраза приоритета 1 выпала из топ-10 или Δ ≤ −5 → сообщение в Telegram (переиспользовать `tools/tg-publish`).
2. Понедельник: автоотчёт из 5 строк — видимость по кластерам, 3 главных падения, 3 роста, заявки за неделю.
3. Раз в месяц: пересмотр списка фраз (сезонность, новые услуги), чистка фраз с нулевым спросом.
4. Раз в квартал: сверка «позиции → заявки» — если кластер в топ-10, а заявок нет, проблема в странице, а не в позициях.

### Фаза 5. Агенты (Hermes / ECC)

Агенты нужны не для сбора цифр (это скрипт), а для работы с смыслом. Все — по правилу propose → approve: агент готовит, человек подтверждает.

| Агент | Задача в этом контуре | Когда |
|---|---|---|
| `seo-specialist` | Разбор недельного среза: почему упало, гипотезы, ТЗ на правку страницы | каждую неделю, 15 мин |
| `loop-operator` | Ведение cron-цикла: сбор → алерт → отчёт, ретраи при сбое API | настройка once + присмотр |
| `doc-updater` | Журнал изменений: что правили на странице и как это отразилось на позициях | после каждой правки |
| `planner` | Пересмотр семантики и приоритетов раз в месяц | monthly |
| `architect` | Схема данных и расширение дашборда (если добавим GEO-видимость в ИИ) | по необходимости |

Отдельно: кластер GEO/AI («видимость в ответах нейросетей») классическим трекером не измеряется — там нужен свой замер упоминаний в ChatGPT/Perplexity/Алисе. Это следующая итерация, не в этой дорожной карте.

## 5. Ограничения, которые нельзя обойти

1. **Вебмастер и GSC не показывают фразы без показов.** Это главный разрыв: по «мёртвым» фразам там пусто. Поэтому трекер/ручной сьём — не роскошь, а обязательный элемент.
2. **Позиция в Яндексе нестабильна** (±5 за неделю — норма, персонализация и регион). Смотреть тренд за 4 недели и долю в топ-10, а не цифру за сегодня.
3. **GSC даёт округлённую позицию** и скрывает данные по редким запросам. Точную цифру по Google даёт только трекер.
4. **Бесплатные лимиты трекеров меняются.** Не строить процесс на «бесплатно навсегда»: закладывать 500–1500 ₽/мес на трекер, если он станет рабочим инструментом.
5. **20 фраз — статистически мало** для выводов; 45–60 по 6 кластерам — минимум, при котором шум не принимается за тренд.

## 6. Критерий готовности всего контура

В понедельник до 12:00 в Telegram приходит отчёт, в котором видно: 3 фразы выросли, 3 упали, видимость по кластерам, заявки за неделю — и ссылка на `/monitoring`. Если через 5 минут после отчёта понятно, что делать, контур работает.
