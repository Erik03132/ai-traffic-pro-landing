## 1. Что сделать в Telegram (3 минуты, руками)

1. Открыть Telegram → ☰ (меню) → **Создать канал** / **New Channel**.
2. **Название канала:** `AI-Traffic PRO` (видно в шапке, до @username).
3. **Описание канала** (вставьте текст из раздела 2).
4. Создать → **Настройки канала → Аватар** → загрузить
   `assets/distribution/telegram-avatar.png` (512×512, терракотовый квадрат с «AT»).
5. **Настройки канала → Имя пользователя** → `aitrafficpro`
   (если занято — `aitraffic_pro` или `ai_traffic_pro`; проверить можно на
   `t.me/aitrafficpro` — если страница не открывается, имя свободно).
6. **Настройки → Описание** → вставить то же описание (дублируется: одно — для
   профиля, второе — для закреплённого поста).
7. Открыть канал → **Закрепить сообщение** → вставить текст из раздела 3.

### Пост 2 — из статьи про CRM и ERP

```
CRM не заменяет учёт. ERP не ведёт продажи.

Это самая частая ошибка в компаниях, где решили «поставить CRM» — и не
самая дорогая. Обычно выходит так: менеджеры заводят сделки в табличке,
бухгалтерия ведёт учёт в 1С, а руководитель считает воронку по отчёту,
который собрали вручную. Систем две, цифры разные.

Разница простая. CRM хранит клиента: переписку, звонки, стадии сделки,
историю общения. ERP хранит ресурсы компании: склад, закупки, себестоимость,
счета, зарплату. Отсюда разные отчёты, разные пользователи и разные
требования к надёжности данных.

Рабочая схема у большинства: CRM принимает заявку и ведёт сделку, а когда
заказ нужно выполнить — передаёт его в ERP. Клиент при этом не переключают
между системами: он общается только с CRM.

Что делать, если CRM уже есть, но её обходят стороной, — [пошаговый разбор в блоге](https://ai-traffic-pro.ru/blog/crm-i-erp-raznica/?utm_source=telegram&utm_medium=social&utm_campaign=crm-i-erp-raznica).
```

### Пост 3 — из статьи про медиаплан и контент-план

```
Медиаплан приводит людей. Контент-план даёт им причину остаться.

контент-план без медиаплана (никто не показывает материалы), либо есть

владельцами, и путать их — обычное дело.

Порядок простой: сначала деньги, потом материалы. Контент-план пишется под
те каналы, которые уже есть в медиаплане.

Подробно — [в статье про медиаплан и контент-план](https://ai-traffic-pro.ru/blog/mediaplan-i-kontent-plan-raznica/?utm_source=telegram&utm_medium=social&utm_campaign=mediaplan-i-kontent-plan-raznica).
```

### Как вставить ссылку, чтобы не было простыни

В постах выше ссылки оформлены как гиперссылки на фразу: в тексте читатель
видит `пошаговый разбор в блоге`, а адрес с метками спрятан внутри.

- **Telegram Desktop:** вставить текст поста → выделить фразу → `Cmd/Ctrl+K`
  → вставить адрес. Либо сразу напечатать `[фраза](адрес)` — приложение
  превратит это в ссылку.
- **Telegram на телефоне:** выделить фразу → «Форматирование» → «Ссылка» →
  вставить адрес.
- **Превью статьи появится в любом случае** — Telegram подтягивает карточку с
  обложкой по первой ссылке, даже если в тексте видна только фраза.

Правила для фразы-ссылки:

- Она должна называть, что человек получит: «пошаговый разбор», «как считать
  окупаемость», «чеклист в блоге». «Узнать подробнее» и «подробнее по ссылке» —
  хуже: не видно, зачем нажимать.
- Одна ссылка на пост. Две и больше — читатель выбирает и не идёт никуда.
- Сырой адрес в тексте не оставляем: он ломает строку и выглядит как спам.

**Если бот есть в админах канала** (`@ai_bureau_new_bot`), пост можно
опубликовать не руками, а через Bot API — тогда вместо гиперссылки будет
кнопка «Читать статью» под постом, а адрес не виден вообще. Пока бот в канал
не добавлен, работаем гиперссылкой: разница только в виде, метки и учёт
работают одинаково.

### Публикация с подтверждением (вместо копипаста)

Черновик можно отправить себе в личный чат с ботом и опубликовать кнопкой —
без ручного копирования и без риска потерять метки:

```bash
python3 tools/tg-publish/send.py --slug <slug> --text-file docs/distribution/posts/<slug>.md --content post-1
```

Под сообщением появятся две кнопки: «✅ Опубликовать в канал» и «❌ Отклонить».
В канал пост уходит вместе с кнопкой «Читать статью →». Подробности и разовая
настройка (бот — админ канала) — `tools/tg-publish/README.md`.

## 5. Правила канала (чтобы не превратить в анонсы)

| Правило | Почему |
|---------|--------|
| Пост — не анонс статьи, а отдельный тезис из неё | «у нас новая статья» читают только те, кто и так на сайте |
| Одна ссылка, в конце | ссылка в первом абзаце режет доверие и переходы |
| Один конкретный вывод на пост | правило проверки текста из `CONTENT_SPEC.md` §4a |
| Никаких цен и обещаний «лидов за неделю» | обещания без проверки = отписки |
| Ритм: 2–3 поста в неделю | лучше 2 сильных, чем 7 анонсов |
| Отвечать на каждый комментарий первые 2 месяца | комментарии = сигнал, что тема зашла |

## 6. UTM-разметка (обязательна, иначе переходы не считаются)

```
https://ai-traffic-pro.ru/blog/<slug>/?utm_source=telegram&utm_medium=social&utm_campaign=<slug>
```

| Канал | `utm_source` | `utm_medium` |
|-------|--------------|--------------|
| Telegram | `telegram` | `social` |
| VK | `vk` | `social` |
| Дзен | `dzen` | `social` |
| Хабр (позже) | `habr` | `referral` |

`utm_campaign` = slug статьи, чтобы в Метрике видеть, какой пост какую
статью привёл. Если из одной статьи выходит несколько постов — добавляется
`utm_content` (`post-1`, `post-2`), чтобы различать их.

**Что происходит дальше (с 10.11.2026).** Сайт запоминает метки первого
захода и передаёт их вместе с заявкой: в сообщении о заявке появляется строка
`📣 Источник: telegram · <статья> · <пост>`, и те же поля лежат в KV-бэкапе.
То есть Метрика показывает канал в цифрах, а заявка — в тексте, без сверки
двух отчётов вручную.

- **Смотреть в Метрике:** Отчёты → Источники → Метки UTM → `utm_source`.
- **Проверять в заявке:** строка «Источник» в сообщении Telegram.
- **Без меток** визит попадёт в «прямые заходы»: Telegram не передаёт referrer.

наказывает в выдаче.
