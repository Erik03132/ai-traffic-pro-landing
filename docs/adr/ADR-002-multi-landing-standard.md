# ADR-002: Единый шаблон страницы услуги (мультилендинг-стандарт)

- **Дата:** 2026-11-01
- **Статус:** принято
- **Контекст:** В проекте 7 страниц услуг (лидогенерация, SEO, SMM, реклама,
  сайты/лендинги, CRM, e-commerce). Изначально каждая страница собиралась
  отдельно: свой набор блоков, свои заголовки, разная длина текста, разъехавшиеся
  H1 — на e-commerce-странице вторая строка H1 вообще содержала текст из другого
  проекта («Искусственные товары и услуги: упаковка, одежда, дизайн, технологии,
  медиа»). Правка одной секции требовала 7 отдельных изменений, а визуальный ритм
  страниц не совпадал: где-то 5 карточек, где-то 3, где-то блок оканчивался
  другим фоном. Плюс содержательные перекосы: у одних услуг 5 пунктов «что
  получите», у других 9; FAQ от 7 до 12 вопросов.

  Альтернативы: (A) оставить 7 независимых страниц, (B) один шаблон + данные,
  (C) генерировать страницы из CMS.

- **Решение:** Один шаблон `src/pages/services/[slug].astro` + данные
  `src/data/services/<slug>.ts` (тип `Service` в `src/data/types.ts`).
  Единый визуальный и содержательный стандарт зафиксирован в
  `docs/design/SPEC-multi-landing.md`.

  Ключевые элементы стандарта:
  1. **Секции** — фиксированный порядок: hero → проблемы → шаги → решение →
     сервисные блоки → FAQ → заявка. Чередование фона `white → stone-50`.
  2. **Нумерация** — eyebrow `[NN / НАЗВАНИЕ]`, основные секции `01–05` подряд
     без пропусков, сервисные блоки всегда `03.5 / 03.6 / 03.7` (чтобы
     добавление блока не сдвигало остальную нумерацию).
  3. **H1** — ровно 2 строки, разделитель `|` в данных, вторая строка рендерится
     в `.accent-italic` (Instrument Serif, терракота). Строка 2 — не длиннее
     одной визуальной строки.
  4. **Сервисные блоки** — опциональные поля `Service` (`platforms`, `channels`,
     `funnelStages`, `cardParts`, …), подключаются в шаблоне по условию
     `service.slug === '<slug>' && service.<field>`.
  5. **Контентные нормы** — `problem` = 3, `solution` = 4, `steps` = 4,
     `outcomes` = 9, `faq` = 13–15, `badge` в формате `A + B`. Нормы одинаковы
     для всех 7 страниц, включая SEO (эталон) и e-commerce (второстепенную).
  6. **Запреты** — третья строка в H1, тени у обычных карточек, вторая кнопка
     в hero, терракота как фон плашки, захардкоженный текст в разметке,
     отдельная секция «Кому подходит».

  Вариант (A) отклонён: цена правки ×7 и уже случившийся дрейф контента.
  Вариант (C) отклонён: CMS не нужна — контент меняется редко и живёт в git,
  а внешняя система добавила бы зависимость без выгоды.

- **Последствия:**
  - Правка общей секции (например, заголовок «С какими проблемами приходят»)
    применяется ко всем 7 страницам одним изменением — проверено.
  - Визуальный и смысловой ритм страниц одинаков: посетитель, зашедший на две
    услуги подряд, видит одну систему, а не два разных сайта.
  - Добавление новой услуги — это новый файл данных + 2–3 сервисных блока,
    шаблон не трогается (кроме подключения блоков).
  - Цена: шаблон `[slug].astro` растёт и содержит условные секции по slug.
    Это осознанный компромисс: ~16 блоков на 7 услуг против 7 копий разметки,
    которые неизбежно разъедутся. Порог для пересмотра — если сервисных блоков
    станет больше ~20, выносить их в отдельные компоненты `ServiceBlocks/*.astro`.
  - Второстепенная услуга (e-commerce) живёт в том же стандарте, но с
    `num: '—'` и `inMain: false` — её нет на главной, но она есть в футере,
    сайте и сайтмапе.

- **Связано:** `docs/design/SPEC-multi-landing.md`,
  `src/data/types.ts` (`Service`), `src/pages/services/[slug].astro`.
