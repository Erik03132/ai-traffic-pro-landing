# ADR-001: API заявок и чата — на Cloudflare Worker, VPS в резерве

- **Дата:** 2026-10-28
- **Статус:** принято
- **Контекст:** Игорь поставил схему размещения: «на T web у нас будут только доменное
  имя с переадресацией на хостинг сайта — он на гитхабе». То есть VPS должен
  исчезнуть из схемы. Дополнительные факторы, которые к этому привели:
  (A) VPS `217.149.23.113` под давлением — swap забит на 3.35 из 4 ГБ, диск 75 %,
  uptime 21 день; (B) внешние LLM-провайдеры с российского IP отдают 403 (Cloudflare
  блокирует российские IP — проверено на `inference-api.nousresearch.com` даже с
  браузерным User-Agent, с финского IP тот же запрос даёт 200); (C) Cloudflare
  блокирует трафик из РФ, значит зависимость от CF — это риск доступности, а не
  отсутствие риска. Альтернативы: (A) оставить Node-сервер на VPS, (B) API на
  Cloudflare Worker, (C) внешний платный хостинг API (Vercel/Render/railway).
- **Решение:** API (заявки + чат-виджет) живёт в Cloudflare Worker
  `ai-traffic-pro-api` → `https://ai-traffic-pro-api.erik03132.workers.dev`.
  Схема: **основной путь — Worker, резерв — Node-сервер на VPS**
  (`https://api.ai-traffic-pro.ru`). Статика — GitHub Pages, как и было.
  LLM переехал внутрь Cloudflare — Workers AI `@cf/meta/llama-3.1-8b-instruct-fp8-fast`
  (на Free — 10 000 нейронов/сутки); модели `deepseek-v4-*`/`kimi-k2.6` требуют
  Workers Paid ($5/мес), поэтому не используются. Логика вынесена в общий модуль
  `server/agent-core.js` — один источник истины для Worker и Node-сервера.
  Бэкап лидов: Workers KV (пишется **до** отправки в Telegram) на Worker,
  JSONL-файл на VPS. Rate limit — встроенные binding'и Worker; CORS — белый список
  origin из переменной окружения.
  Вариант (C) отклонён: лишний платный сервис и та же зависимость от чужой
  доступности из РФ, что и Cloudflare, но без бесплатного тарифа.
- **Последствия:** Сайт больше не зависит от VPS — его можно выключить. Внешние
  LLM из РФ перестают быть проблемой (Worker исполняется на edge, где CF не
  блокирует сам себя). Появляется зависимость от доступности Cloudflare из РФ —
  закрыта резервом на VPS: при сетевой ошибке клиент уходит на резервный адрес.
  Повтор запроса делается **только** при сетевой ошибке: на 5xx ответ сервера
  означает, что заявка могла уйти, повтор дал бы клиенту две заявки.
  Кастомный домен `api.ai-traffic-pro.ru` потребовал бы переноса NS всей зоны
  (CNAME-setup и subdomain-setup доступны только на Business/Enterprise) — это
  отдельная задача, и после неё резерв на `api.ai-traffic-pro.ru` стал бы той же
  инфраструктурой Cloudflare, поэтому при переносе NS резерв переводится на
  отдельный хост VPS.
