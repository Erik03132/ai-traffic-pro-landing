# Поток производства лендингов

Hallmark ставит дизайн и проверяет его. Бриф, текст, SEO, аналитику и деплой делаем мы.
Документ фиксирует порядок, чтобы второй и десятый лендинг шли так же быстро, как первый.

Инструмент: `~/.config/opencode/skills/hallmark/` (MIT, Together AI, commit `407fa68`), вызов — `/hallmark` или «собери лендинг по hallmark».
Скрипты: `theme.mjs` (темы), `sloplint.mjs` (линтер), `--render` работает (Chrome + puppeteer-core установлены, 8 ширин).

## Шаг 0. Стек — до всего остального

| Что делаем | Стек | Почему |
|---|---|---|
| Одна страница: лендинг, промо, квиз | чистый HTML + CSS, как отдаёт Hallmark | нет сборки, нет зависимостей, деплой куда угодно, открывается за 200 мс |
| Многостраничник, блог, каталог | Astro | Hallmark даёт дизайн, переносим в компоненты |

Не тащить Astro в одностраничник: это +сборка, +зависимости и −скорость при нулевой выгоде.

## Шаг 1. Бриф — 30 минут, без него не начинаем

Пять вопросов, ответы в `clients/<slug>/brief.md`:

1. **Что посетитель должен сделать** — одно действие, не три.
2. **Кому продаём** — кто он и что уже пробовал.
3. **Чем докажем** — цифры, кейсы, скриншоты. Только реальные: выдуманные факты — Floor-гейт, сборка не сдаётся.
4. **Тон** — три прилагательных и один пример сайта, который нравится.
5. **Ограничения** — логотип, цвета, юридические требования, срок.

## Шаг 2. Тема — 10 минут

```bash
node ~/.config/opencode/skills/hallmark/scripts/theme.mjs deal \
  --genre modern-minimal --prompt "<суть из брифа>" --n 3
```

Три варианта на выбор. Лог `.hallmark/log.json` помнит, что уже выдавалось: двум клиентам одна тема не достанется.

## Шаг 3. Hero первым — 1 час

Собираем только первый экран. Рендерим, смотрим холодным взглядом, показываем.
Страницу целиком до утверждения hero не строим — иначе переделываем всё.

## Шаг 4. Сборка — 1–2 часа

Анатомия страницы по задаче (`theme.mjs draw --job visit|buy|book|…`), тексты — наши, по `brand-voice`.
Правила текста те же, что в `docs/CONTENT_SPEC.md`: без выдуманных цифр, без гарантий результата.

## Шаг 5. Проверка — 30 минут, три гейта

1. **Линтер.** `node ~/.config/opencode/skills/hallmark/scripts/sloplint.mjs <файл> --render --tier floor` — 8 ширин в реальном Chrome.
2. **Наш чек-лист приёмки** (ниже).
3. **Ревью по брифу.** `egm-review lite`: отвечает ли страница на вопрос, с которым пришёл посетитель.

## Шаг 6. Сдача — 30 минут

Мета в лимитах, canonical, OG, один H1, sitemap и robots, дубли → 301, Метрика и цели, GSC.

## Чек-лист приёмки (наш, не Hallmark)

| Проверка | Норма |
|---|---|
| `title` | ≤ 60 символов |
| `description` | 140–160 символов |
| `canonical` | совпадает с адресом страницы |
| `H1` | ровно один |
| Дубли (`www`, `http`, без слэша) | 301 в один хоп |
| Контраст текста | AA |
| `prefers-reduced-motion` | учтён |
| Ширины 375 / 768 / 1280 | без горизонтального скролла |
| Вес страницы | ≤ 500 КБ без фото |
| Форма | отправляется по-настоящему, есть состояние ошибки |
| Аналитика | счётчик + цель на целевое действие |
| Индексация | sitemap обновлён, GSC принял |

## Экономика

| | Значение |
|---|---|
| Время на лендинг | 3,5–5 часов |
| Токены | ~15k на вызов скилла + проверки; на платном проекте несущественно |
| Повторное использование | темы и гейты — бесплатно, лог тем не даёт повторяться |

## Чего не делаем

- Не применяем Hallmark к существующим сайтам без явной просьбы — скилл это запрещает сам, и это правильно: переделка ради линтера ломает живую дизайн-систему.
- Не гонимся за 100 % sloplint. House style (eyebrow, длинное тире, tracked-caps) — вкус, а не дефект. Смотрим только `--tier floor` и только то, что видно на телефоне.
- Не сдаём без реальных доказательств: Floor-гейт «invented facts» — единственный, который нельзя обойти «на усмотрение дизайнера».
